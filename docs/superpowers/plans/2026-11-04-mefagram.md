# Mefagram Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship a private, persistent, agent-editable diagram workspace with a useful Mac reading interface.

**Architecture:** Next.js serves the React Flow viewer, authenticated HTTP routes and MCP endpoint. One transactional diagram service governs Postgres persistence and revisions for all callers. Local PGlite provides real filesystem persistence; hosted Postgres is mandatory on Vercel.

**Tech Stack:** TypeScript, Next.js, React, React Flow, ELK, Better Auth, Drizzle, PGlite/pg, MCP SDK, Vitest and Playwright.

**Spec:** docs/superpowers/specs/2026-11-04-mefagram-design.md

## Global Constraints

- Zero additional service or SDK fees; no silent paid plans.
- Default Mac reading/analysis, agent-led editing, Turkish interface copy.
- Public source repo must contain no private diagrams, database files or credentials.
- Every diagram read/write requires ownership; every update requires expected revision.
- No mock database, browser-only canonical storage, or production filesystem fallback.
- Report actual Dot connectivity separately from protocol/client tests.

## Review Focus

- Concurrent writers and repeated requests must not silently lose updates or duplicate mutations.
- Malformed imports, graph cycles in hierarchy, dangling edges and unsafe links must be rejected before persistence.
- Unauthenticated visitors and a different authenticated user must not discover private content or revisions.
- Restarting the server or creating a new browser session must retain saved content.
- An expired/revoked token or failed save must not appear successful to the agent or reader.

### Task 1: Domain and transactional persistence

**Files:** package.json; tsconfig.json; next.config.ts; src/lib/diagrams/{schema,patch,service,repository,seed}.ts; src/lib/db/{index,schema,migrate}.ts; tests/diagrams.test.ts; scripts/bootstrap.ts.

**Interfaces:** DiagramDocument is the portable schema. DiagramService exposes list(ownerId, query), get(ownerId,id), create(ownerId,input,mutationId), patch(ownerId,id,expectedRevision,operations,mutationId), revisions(ownerId,id), restore(ownerId,id,revision,expectedRevision,mutationId). Consumers receive saved records with id, revision and timestamps. Repository transactions perform compare-and-swap and append the audit record together.
